RutaPropósitoEditable

Importante: Git no incluye el motor completo de Experience Builder. Cada developer debe descargar e instalar la misma versión de Developer Edition. El repositorio conserva el código propio y los builds publicables, no node_modules ni toda la distribución de Esri.

2. Requisitos

  • Windows con Git.
  • Acceso al repositorio LeonelRiveroEsri/GIS_QB.
  • ArcGIS Experience Builder Developer Edition en la misma versión usada por el equipo.
  • Node.js y npm compatibles con esa versión de Experience Builder.
  • Cuenta y Client ID del mismo portal de ArcGIS Online o Enterprise.
  • Python 3 para ejecutar la sincronización.
Nunca guardar tokens, contraseñas, secretos OAuth ni archivos de sesión dentro de Git. El Client ID puede configurarse localmente, pero las credenciales personales no se versionan.

3. Instalación desde cero

3.1 Clonar GIS_QB

$gitRoot = "$env:USERPROFILE\Documents\GitHub"
New-Item -ItemType Directory -Path $gitRoot -Force
git clone https://github.com/LeonelRiveroEsri/GIS_QB.git "$gitRoot\GIS_QB"
$repo = "$gitRoot\GIS_QB"
git -C $repo status

3.2 Instalar Experience Builder

Descargar la versión acordada por el equipo, descomprimirla en una ruta local y definirla:

$exb = "D:\EXB_DEV"

cd "$exb\server"
npm ci

cd "$exb\client"
npm ci

Comprobar que Node y npm pertenecen al mismo ambiente:

where.exe node
where.exe npm
node --version
npm --version
Si node y npm apuntan a instalaciones incompatibles, la exportación puede fallar. Corregir el PATH antes de continuar.

4. Instalar los widgets desde Git

Detener el cliente de Experience Builder antes de agregar o renombrar carpetas.

$repo = "$env:USERPROFILE\Documents\GitHub\GIS_QB"
$exb = "D:\EXB_DEV"

Copy-Item -Recurse -Force `
  "$repo\widgets\hidrograma-interactivo" `
  "$exb\client\your-extensions\widgets\hidrograma-interactivo"

Copy-Item -Recurse -Force `
  "$repo\widgets\hidrograma-interactivoV2" `
  "$exb\client\your-extensions\widgets\hidrogramaV2"
El mapeo V2 es intencional: la carpeta del repositorio es hidrograma-interactivoV2, pero el manifest y la Experience usan el nombre interno hidrogramaV2.

5. Importar las Experiences

Experience Builder importa un ZIP cuyo index.html está directamente en la raíz. Crear paquetes temporales a partir del build versionado:

$repo = "$env:USERPROFILE\Documents\GitHub\GIS_QB"
$imports = "$env:TEMP\GIS_QB_imports"
New-Item -ItemType Directory -Path $imports -Force

Compress-Archive `
  -Path "$repo\experiences\hidrograma-interactivo\app\*" `
  -DestinationPath "$imports\Hidrograma Interactivo.zip" `
  -Force

Compress-Archive `
  -Path "$repo\experiences\hidrograma-interactivoV2\app\*" `
  -DestinationPath "$imports\Hidrograma Interactivo V2.zip" `
  -Force

Luego:

  1. Iniciar server y client.
  2. Abrir https://localhost:3001/.
  3. Ingresar al mismo portal usado por el equipo.
  4. Elegir Experience → Import → Import from my computer.
  5. Importar ambos ZIP y guardar las Experiences.
Los IDs locales pueden cambiar. En una máquina pueden ser 0 y 1, y en otra 4 y 5. Nunca suponer el ID sin revisar server/public/apps.

6. Ejecutar, editar y probar

Terminal del servidor:

cd D:\EXB_DEV\server
npm start

Terminal del cliente:

cd D:\EXB_DEV\client
npm start

Editar los widgets en:

D:\EXB_DEV\client\your-extensions\widgets\hidrograma-interactivo
D:\EXB_DEV\client\your-extensions\widgets\hidrogramaV2

Antes de exportar:

  • La Experience abre sin errores.
  • El widget muestra el cambio esperado.
  • Filtros, mapas y exportaciones funcionan.
  • No hay referencias al widget de perfiles.
  • La Experience fue guardada en Builder.

7. Exportar y sincronizar

Descargar desde Experience Builder las dos aplicaciones actualizadas y conservar estos nombres:

D:\EXB_DEV\exports\Hidrograma Interactivo.zip
D:\EXB_DEV\exports\Hidrograma Interactivo V2.zip

Ejecutar primero una simulación:

python D:\EXB_DEV\sync_repository.py `
  --project-root "D:\EXB_DEV" `
  --repository-root "$env:USERPROFILE\Documents\GitHub\GIS_QB" `
  --skip-export `
  --dry-run

Si la validación es correcta:

python D:\EXB_DEV\sync_repository.py `
  --project-root "D:\EXB_DEV" `
  --repository-root "$env:USERPROFILE\Documents\GitHub\GIS_QB" `
  --skip-export

7.1 Alternativa inicial si todavía no se instaló el script

El developer puede expandir cada ZIP en una carpeta temporal, comprobar su raíz y reemplazar únicamente el destino correspondiente:

$repo = "$env:USERPROFILE\Documents\GitHub\GIS_QB"
$zip = "D:\EXB_DEV\exports\Hidrograma Interactivo V2.zip"
$stage = "$env:TEMP\GIS_QB_stage_v2"
$destination = "$repo\experiences\hidrograma-interactivoV2\app"

# Confirmar que el destino está dentro del clon antes de eliminarlo.
$repoFull = [IO.Path]::GetFullPath($repo)
$destinationFull = [IO.Path]::GetFullPath($destination)
if (-not $destinationFull.StartsWith($repoFull, [StringComparison]::OrdinalIgnoreCase)) {
  throw "Destino fuera del repositorio: $destinationFull"
}

if (Test-Path -LiteralPath $stage) {
  Remove-Item -LiteralPath $stage -Recurse -Force
}
Expand-Archive -LiteralPath $zip -DestinationPath $stage

if (-not (Test-Path -LiteralPath "$stage\index.html")) {
  throw "El ZIP no contiene index.html directamente en la raíz"
}

if (Test-Path -LiteralPath $destination) {
  Remove-Item -LiteralPath $destination -Recurse -Force
}
Copy-Item -LiteralPath $stage -Destination $destination -Recurse

Repetir con la Experience original, cambiando ZIP y destino. Para los widgets, copiar desde el ambiente de Builder al clon con el mapeo inverso:

Copy-Item -Recurse -Force `
  "D:\EXB_DEV\client\your-extensions\widgets\hidrogramaV2\*" `
  "$repo\widgets\hidrograma-interactivoV2"
El resultado correcto actualiza el código fuente de ambos widgets y deja index.html directamente dentro de cada carpeta experiences/*/app.

8. Commit, revisión y push

8.1 Crear una rama

$repo = "$env:USERPROFILE\Documents\GitHub\GIS_QB"
git -C $repo switch main
git -C $repo pull --ff-only
git -C $repo switch -c feature/descripcion-corta

8.2 Revisar

git -C $repo status
git -C $repo diff --stat
git -C $repo diff -- widgets

8.3 Preparar únicamente el alcance autorizado

git -C $repo add -- `
  widgets/hidrograma-interactivo `
  widgets/hidrograma-interactivoV2 `
  experiences/hidrograma-interactivo/app `
  experiences/hidrograma-interactivoV2/app

git -C $repo diff --cached --stat

8.4 Commit y push

git -C $repo commit -m "Describe el cambio"
git -C $repo push -u origin feature/descripcion-corta

Abrir un Pull Request hacia main. Para trabajo colaborativo, evitar pushes directos a main.

9. Ver localmente la Experience de producción

No abrir index.html mediante file://. Servir la carpeta con HTTP:

cd "$env:USERPROFILE\Documents\GitHub\GIS_QB\experiences\hidrograma-interactivoV2\app"
python -m http.server 8080

Abrir http://localhost:8080/.

Experience Builder usa service workers. Si aparece una versión anterior, cerrar las pestañas, borrar los datos del sitio o probar en una ventana privada. Cada exportación puede incrementar la carpeta interna cdn/N; esto es normal y evita caché obsoleta.

10. Trabajo por roles

RolEntregaResponsabilidad
Developerwidgets/**Implementar y probar el código fuente del widget.
Analista GISexperiences/**/appIntegrar el widget, configurar la Experience, probar y exportar.
RevisorPull RequestConfirmar que widget fuente y Experience compilada son consistentes.

Una rama puede recibir dos commits:

1. Improve Hidrograma V2 widget
2. Rebuild Hidrograma V2 experience
El código nuevo del widget no entra automáticamente en un build ya exportado. Alguien debe compilar y volver a descargar la Experience. main debería recibir el widget y su Experience reconstruida como una unidad coherente.

11. Problemas frecuentes

SíntomaAcción
El widget no aparece en Builder.Confirmar la carpeta y el manifest.json; reiniciar npm start del cliente.
npm informa una versión distinta de Node.Ejecutar where node y where npm; corregir el PATH.
La Experience sigue mostrando el texto anterior.Guardar, recompilar, exportar nuevamente y limpiar la caché/service worker.
La importación falla.Verificar misma versión de Experience Builder, mismo portal y index.html en la raíz del ZIP.
Git muestra muchos renombrados cdn/6 → cdn/8.Es esperado cuando cambia el número de build. Revisar que index.html apunte al nuevo directorio.
La Experience contiene perfiles.No publicar. Corregir la Experience editable y exportarla nuevamente.

12. Lista final antes del Pull Request

  • La rama parte de la última versión de main.
  • Los widgets fuente contienen los cambios.
  • Las Experiences fueron guardadas y exportadas nuevamente.
  • El texto o función nueva existe en el bundle compilado.
  • No hay secretos ni archivos temporales.
  • No hay widgets de perfiles ni recursos de otros clientes.
  • La Experience de producción abre mediante HTTP.
  • El Pull Request explica el cambio y las pruebas realizadas.
